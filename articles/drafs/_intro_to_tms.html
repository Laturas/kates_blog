2. Intro to TMs and Common Notations

A TM is an extremely simple model of a computer. At any given point in time, it has exactly one state it is in. It runs on a tape, a string of infinite symbols in both directions of which it looks at exactly one symbol at any given time, and a table of instructions, which tell the TM how to run.

The TM runs in steps, which is defined as the execution of a single instruction. One instruction is made up of three components:

  • The value to write into the current cell it is looking at
  • The direction to move (left or right), by exactly one cell
  • Which state to enter next

Which instruction gets executed at any given time is determined by:

  • The symbol it is currently looking at
  • The state it is currently in

Distinct symbols are usually denoted with an integer (0 <=), and states are denoted with a letter (A-Z). Thus, a turing machine program is representable by a lookup table, that looks something like the following:

State 0 1
A 1RB 0RB
B 1LA 0LA

The first cell and first column is thus read as: "Upon reading a 0 while in state A, write a 1 into the current cell, shift 1 cell right, then enter state B"

Now, there's one last thing to cover: the HALT instruction. The HALT instruction is special, because it tells the machine to stop running, and whatever is on the tape when it is finished executing is considered the output of that TM program.

This necessitates the question: How do we represent this all in a compact form? Tables are helpful, but when you have a lot of machines it would be really helpful to have a way of referring to them.

TM Codes

We can compactify a table into a string by denoting each instruction by 3 characters splitting each state with an "_", and having the read symbol act as an index within each state. As an example, 1RB0RB_1LA0LA is equivalent to the table at the beginning of chapter 2.

So how do we represent the HALT state? There are two distinct common conventions with slightly different interpretations. "---" is used to indicate an instruction that's undefined, either because it is never executed, or because we don't know whether it is executed. Meanwhile, "1RZ" is used to indicate an explicit halting instruction, meaning it is both reached, and stops the program. "Z" is used as a stand-in for an undefined transition. In the early days, "H" used to be the common denotation for this state, but it came too early in the alphabet and caused problems, so Z was switched to instead.

This raises the natural question of course of what happens if we need to represent a TM with more than 25 states or 10 symbols? To which the answer is, "ah, don't worry about it". (There's no agreed upon solution to this yet).

This allows us to infer some information rather quickly. As an example, we can deduce from the TM code 1RB3LA1RA0LA_2LA---1RZ3RA that the instruction for reading a 1 in state B is never reached, and the machine halts upon reading a "2" in state B.

Compressed Tape Notation

When discussing the current state of a tape that a machine is working on, it's common to write it out with a compressed form, like so:

\[0^\infty (1^{50}) \text{ A> } ((101)^{10}111)^{13} 0^\infty\]

This seems utterly horrifying to read, but it's actually fairly straightforward. Repetitions are denoted with exponential notation, so 1^50 means "fifty 1's in a row", and the infinite zeros on either end indicate that there are infinitely many untouched zeros from then on shooting off into infinity. (You'll also often see "$" be used as a shorthand for 0^infinity. They mean the same thing).

The "A>" is known as directed head notation. The arrow points to the current symbol the machine is looking at, and the letter indicates the current state of the machine at that step.
